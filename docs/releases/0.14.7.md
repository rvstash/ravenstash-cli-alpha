# RVS 0.14.7

RVS 0.14.7 is the first release on the rolling `v0` channel and makes portable
installation available everywhere, including CI.

## Portable installation

`install.sh` now accepts `RVS_INSTALL_METHOD=portable`, which installs the signed
portable archive on any supported Linux system without configuring APT. This
suits ephemeral CI runners:

```bash
curl -fsSL https://ravenstash.com/install.sh \
  | RVS_INSTALL_METHOD=portable RVS_INSTALL_NO_BANNER=1 \
      RVS_INSTALL_NO_HINTS=1 bash
```

With the portable method, `RVS_INSTALL_VERSION=X.Y.Z` or `X.Y.ZrcN` selects an
exact release. The archive passes the same signed inventory and checksum
verification as the default release.

## Rolling `v0` channel

All pre-1 stable releases now share one `v0` channel across APT, portable
archives, Nix, Homebrew, and WinGet. Plain `rvs update` advances to the newest
stable `v0` release, and `rvs update --to 0.MINOR` selects the latest stable
patch of one minor line without pinning it.

The APT repository now publishes the single suite `v0`; the former `v0.14`
suite is no longer published. Existing APT installations reconfigure their
source once:

```bash
curl -fsSL https://ravenstash.com/install.sh | RVS_INSTALL_REPAIR=1 bash
```

Portable installations of 0.14.6 or earlier cannot read the `v0` channel
manifest. Reinstall them once with the installer; later updates use
`rvs update` as usual.

## Package evidence

`rvs art evidence stage` attaches evidence such as a CycloneDX SBOM to a package
before it is published with its native client. `rvs art evidence status` reports
processing, optionally waiting for completion, and `rvs art evidence sbom`
downloads the analyzed SBOM. Staging never publishes the package itself.

## Account and repository display

User and organization accounts are shown unambiguously as `user:USERNAME` and
`org:HANDLE`. Both typed forms are accepted as selectors, and bare handles keep
working. `rvs art repo list` also shows the effective `Read`, `Publish`, or
`Admin` access for each repository.

## Release operations

Signed APT metadata is now refreshed daily. Each refresh still issues a
seven-day `Valid-Until`, so several consecutive missed runs are needed before
public metadata expires.
