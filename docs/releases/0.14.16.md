# RVS 0.14.16

RVS 0.14.16 adds package tag management for npm and makes deleting content safer.

## Package tags

`rvs art package tag list|set|delete` manage npm distribution tags. Unlike OCI
tags, package tags move: `set` creates a tag or points it at another version.
`--expect-revision` applies a change only if nobody changed the tag since
`tag list` showed its revision. Moving `latest` and deleting a tag ask for
confirmation unless you pass `--yes`.

`rvs art package show` prints each package's tags and the tags on every version.
A tag whose version cannot be installed from the repository is marked, with the
reason, and `latest` falls back to the best installable version. Callers without
publish access see only the tags that resolve.

This release needs the current Ravenstash API: the package API now reports
`tags` instead of `dist_tags`, so earlier `rvs` releases show no distribution
tags.

## npm

- `rvs npm dist-tag ls` reads tags with a read-only credential instead of
  requesting publish access.
- `rvs npm dist-tag add` and `rm` ask for confirmation before changing `latest`
  or removing a tag. In CI, pass `--rvs-yes`.
- `rvs npm undeprecate` now works; it previously received a read-only credential.
- `rvs npm` recognizes `publish`, `unpublish`, `deprecate`, and `dist-tag` only as
  the npm command itself, so `rvs npm install unpublish` no longer asks for
  publish or delete authority.

## Deleting content

Deleting package content moves it to the repository trash, where it can be
restored in the web app until it is permanently deleted. The delete commands say
so and name what they deleted. `rvs npm unpublish` requests delete authority, so
an existing publish-only token can no longer unpublish; mint one with
`--access admin`.

Update with `rvs update --apply`.
