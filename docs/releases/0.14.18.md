# RVS 0.14.18

RVS 0.14.18 repairs updates of portable Linux installations, shows where each
package tag comes from, and follows the final names of the Ravenstash API. It
is the last release from the public alpha repository before the CLI moves to
its final repository.

## Updating

`rvs update --apply` now works on portable glibc Linux installations (amd64 and
arm64). Earlier portable archives for these platforms contained symbolic links
that the updater refuses, so the update stopped with "unsafe path".
Installations of 0.14.17 and earlier can update to this release. The glibc
archive ships `ravenstash` and `docker-credential-rvs` as regular files, like
the other portable archives, and is about twice as large; the Debian package is
unchanged.

When APT cannot install the version selected with `rvs update --to`, `rvs`
reinstalls the previous version and reports the failure. `rvs update` refuses a
signed release-channel manifest that does not state its validity period.

## Package tags

`rvs art package tag list` lists every tag that installs in the repository
resolve: the repository's own tags and the tags its upstreams define. The
`Source` column says where each tag comes from, and `Read-only` marks the tags
an upstream defines, which can only be changed in their source.
`rvs art package show` names the source of upstream tags, and `tag set`,
`tag delete`, and `rvs npm dist-tag add` and `rm` explain why a change that
names an upstream tag or version is refused. The repository's own `latest` tag
can be deleted when an upstream supplies some of the package's versions.

## Ravenstash API names

This release follows a naming change in the Ravenstash API; earlier `rvs`
releases cannot create evidence intents against it.

- Byte sizes are `size_bytes` in evidence intents and in OCI manifests and
  their descriptors.
- An evidence intent names the published files it is bound to as
  `bound_file_ref` and `bound_file_refs`.
- The matches of an ambiguous repository selector carry `account_handle`.
- Deleting a manifest that an image index references answers the error code
  `ManifestReferencedByIndex`.

Scripts that read these fields from `--json` output or from the API need the
new names.

Update with `rvs update --apply`.
