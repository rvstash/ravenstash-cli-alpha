# `rvs` 0.7.0

`rvs` 0.7.0 separates authentication from local profile and acting-account
context, adopts private-mirror terminology, and removes compatibility aliases
from the public command surface.

## Changed

- `rvs auth` now contains only authentication and credential-storage actions.
  Named CLI configuration is managed through `rvs profile`, while
  authorization and metering context is managed through `rvs account`.
- `rvs profile current` shows non-secret endpoint and credential-store
  configuration. `rvs context current` verifies the user and shows the effective
  local profile, acting account, package target, and selection provenance.
- Official and custom direct-install targets are private mirrors. Their target
  forms are `mirror:source` and `custom-mirror:name`, managed through
  `rvs pkg mirror`.
- Repository and target selections retain typed stable identities so mutable
  display names cannot silently rebind local context.
- `rvs repo` manages package repositories. `rvs ci` remains a placeholder.

## Removed commands and options

The 0.7 command surface does not retain compatibility aliases:

| Removed | Use instead |
| --- | --- |
| `rvs auth profile ...` | `rvs profile ...` |
| `rvs profile switch` | `rvs profile use` |
| `rvs account switch` | `rvs account use` |
| `rvs pkg cache ...`, `rvs pkg remote-cache ...` | `rvs pkg mirror ...` |
| `cache:source`, `custom-cache:name` | `mirror:source`, `custom-mirror:name` |
| `rvs packages` | `rvs pkg` |
| `rvs auth keyring ...` | `rvs auth storage ...` |
| `--ecosystem`, `-e` | `--registry-kind`, `-k` |
| generic `rvs pkg --repo` | `rvs pkg --target` |
| wrapper `--rvs-repo` | `--rvs-target` |
| `rvs pkg repo set-upstream`, `clear-upstream` | `rvs pkg repo upstream add`, `remove` |

Package and helper commands that use `--repo` to identify a repository resource
retain that option; it is not a context-selection alias.

## Compatibility

This release starts the `v0.7` compatibility channel. Existing installations
must opt in explicitly:

```bash
rvs upgrade --to v0.7
```

Existing profiles and credentials remain readable. Scripts must adopt the
canonical commands and target forms listed above before upgrading.
