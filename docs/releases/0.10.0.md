# `rvs` 0.10.0

This release starts the `v0.10` compatibility channel and targets the reviewed,
unstable DevAPI `/v0` contract. Upgrade existing installations explicitly with
`rvs upgrade --to 0.10`.

Deployment prerequisite: the target DevAPI must expose `/v0/meta` and
`/v0/remote-caches`. The older `/v0/remote-repositories` contract is insufficient.
Publish this channel without promoting the default installer until the matching
backend contract is deployed to the public API.

- DevAPI version selection is centralized; the client detects mismatched server
  version headers. API generation and CLI release version remain independent.
- Account, repository, package, and remote-cache commands consume the typed v0
  responses and public resource references. Upstream edits include the current
  configuration revision to detect concurrent changes.
- `rvs art` and `rvs artifacts` are equivalent product groups. Repository
  management lives under `rvs art repo`; the top-level `rvs repo` shortcut is
  removed. The hidden `rvs pkg` transition alias still emits a deprecation warning.
- Publishing uses format-aware confirmation; unattended publishing requires
  `--yes`. `rvs shell` is removed; runtime shell setup remains available.
- Existing profiles, credentials, selected accounts, and targets are retained.

Development integration verified device authorization and refresh, mirror
creation, PyPI/npm/Maven downloads using device and automation credentials,
remote-cache population, and revocation of issued package capabilities.
