# RVS 0.12.0

This release adds scoped automation credentials and native registry token exchange.
Browser login remains the preferred interactive flow; its refresh credential uses
the configured keyring, vault, or pass store. Explicit plaintext storage remains
available. `RVS_TOKEN` overrides the login session and accepts personal PATs,
organization-scoped PATs, or shared organization automation tokens.

Native package commands exchange the current identity for a repository- and
registry-scoped `rvs_slt` credential. Static native configurations use a four-hour
credential because the native clients do not provide a general renewal callback.
Generate a token manually with:

```sh
rvs artifacts auth print-token --target namespace/repository --kind pypi --access read --duration 4h
```

Manual lifetimes range from 15 minutes to 12 hours. Token output is secret;
keep it out of logs. Direct use of long-lived automation credentials in native
registries is discouraged, controlled by account policy, and may be removed.
Revoked or narrowed sources also bound derived credentials; issuance retries use
one stable operation identity and never silently mint duplicate credentials.

This release requires the Task 083 service deployment. Existing sessions and
legacy tokens are invalidated by that coordinated cutover: log in again or create
new automation credentials. Version 0.12.0 uses the `v0.12` APT channel; users on
`v0.11` switch explicitly with `rvs upgrade --to 0.12.0`.
